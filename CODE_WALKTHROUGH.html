Phase 1 — Baseline Reproduction & AttentiveSpecCNN core, all traced

Pipeline order: build_manifest.py → build_balanced_subset.py → split_manifest.py → {paper_baseline.py, train.py} → explain.py / cross_dataset.py. This is the reproduction of Gujjar et al. 2024 plus the proposed detector; every script here has a direct trace into report_tables.tex / main.tex.

build_manifest.py

merges 6 raw corpora into one labeled, speaker-tagged manifest CSV
In paper

Purpose. Walks six heterogeneous audio-deepfake corpora on disk and merges them into one labeled CSV manifest (filepath, label, dataset_source, generator, speaker, extra), with a speaker column deliberately engineered for later speaker-disjoint splitting.

Top-level: patches csv.field_size_limit(sys.maxsize) (with an OverflowError fallback to 2**31-1) because some MLAAD meta.csv transcript fields exceed Python's default 131072-byte field limit.

  • load_asvspoof_labels(ds1_root) -> list[dict] — loads ASVspoof2021 DF-eval. Disambiguates among multiple near-identical trial_metadata.txt files found via rglob (glob order is filesystem-dependent) by filtering for paths containing /DF/ or DF-keys. Parses protocol lines (speaker, filename, label at column 5), walks every flac/ dir under any DF_eval path, emits rows with speaker="asv:<speaker>".
  • load_seedtts_style(ds2_root) -> list[dict] — loads dataset_2. real_samples/ → real; every other subdir (VALL-E, NaturalSpeech3, etc.) → fake, generator = folder name. Real speakers derived from LibriSpeech filename convention (ds2:<speaker>); fake files get one-per-file speaker groups (ds2g:<stem>) — deliberately prevents leakage grouping since fake filenames have no shared speaker scheme.
  • load_mlaad(ds3_root) -> list[dict] (with nested helper mlaad_speaker(original_file, fallback)) — loads MLAAD v5 (fake-only). mlaad_speaker parses the reader out of original_file's path (.../wavs/<file> → parts[-4], or via a by_book anchor) so the same TTS-source reader stays grouped across generators. Main body doesn't trust meta.csv's language segment in path (~1000 rows point at a wrong lang dir); instead joins the filename onto the filesystem-verified model_dir.
  • load_asvspoof2019_la(root) -> list[dict] — loads ASVspoof2019 LA train/dev/eval CM protocols. Speaker = asv19:<spk>; generator = attack ID or "bonafide".
  • load_in_the_wild(root) -> list[dict] — loads In-the-Wild OOD corpus; label inferred from path keywords; per-file speaker groups (only ever used as a held-out cross-corpus target, so no leakage concern).
  • load_arabic_arad(root) -> list[dict] — loads the Arabic ArAD corpus (from download_arabic.py's output); per-file speaker groups.
  • main() — argparse (--root, --out), calls all six loaders, concatenates, writes the fixed-fieldname CSV, prints real/fake totals.

build_balanced_subset.py

water-filling downsample of the ~97%-fake manifest to a balanced, generator-diverse subset
In paper

Purpose. Downsamples the fake-dominated merged manifest into a class-balanced, source/generator-diverse subset, avoiding the trivial "always predict fake" shortcut and a fake class dominated by one dataset/generator.

  • water_fill(capacities: dict, budget: int) -> dict — the core allocation algorithm, reused twice more elsewhere in the codebase. Distributes budget as evenly as possible across keys, capped per key: loop while remaining budget and active keys exist, take an even share = max(1, remaining // len(active)) per active key (capped by that key's remaining room), drop exhausted keys from active. Classic max-min-fairness water-filling.
  • sample_fake(fake, n_target, seed) -> DataFrame — two-level water-filling: first across dataset_source, then within each source across generator. Directly imported and reused by cross_dataset.py's build_fold.
  • main() — argparse (--manifest, --out, --ratio=1.0, --max_real, --seed=42). Splits real/fake, computes n_fake = round(ratio*len(real)), calls sample_fake, shuffles, writes, prints composition stats.
Paper traceReferenced by name in README and CLAUDE.md ("class-balanced subset via water-filling"); underlies Table I's balanced counts. The same water-filling primitive resurfaces at train-sampling time in overnight_pipeline.py's sample_source — same idea, independently reused, not code-shared.

split_manifest.py

speaker-disjoint train/val/test split — the leakage fix over the reference paper
In paper

Purpose. Produces speaker-disjoint splits via StratifiedGroupKFold, fixing the bug where a speaker's utterances could straddle train and test.

  • _grouped_holdout(df, frac, seed) -> (rest_df, holdout_df) — computes n_splits = max(2, round(1/frac)), builds StratifiedGroupKFold, but only consumes the first fold (next(sgkf.split(...))) as the holdout — a repurposing trick rather than using all K folds.
  • main() — argparse (--manifest, --out_dir, --val_frac=0.1, --test_frac=0.1, --seed=42). Two-stage carve: split off test via _grouped_holdout(df, test_frac), then split val from the remainder via a renormalized fraction val_frac/(1-test_frac). Runs an explicit assertion that all pairwise speaker-set intersections between splits are empty ("speaker leak between splits!").
Paper traceThe "speaker-disjoint StratifiedGroupKFold" fix is the headline methodological correction over the reproduced paper — stated throughout main.tex/README as the reason the reproduced baseline EER differs from the original's inflated accuracy.

paper_baseline.py

reproduces the original paper's MFCC→GNB→NMF→{GNB,LR,RF,KNN} chain on the leakage-free splits
In paper

Purpose. Honest classical baseline the deep model must beat. Constants: SAMPLE_RATE=16000, N_MFCC=40, CACHE_DIR="features_cache"; a module-level torchaudio.transforms.MFCC instantiated once.

  • _file_features(filepath) -> ndarray — loads via deepfake_dataset.load_audio, downmixes/resamples, computes MFCCs, reduces to a 2*N_MFCC-dim [mean, std] vector; returns a zero vector on any decode failure.
  • extract_split(csv_path) -> (X, y) — MD5-hashes the file list for a cache key, loads a cached .npz if present, else extracts via Parallel(n_jobs=-1, prefer="threads") and caches.

  • _evaluate(clf, Xtr, ytr, Xte, yte) -> dict — fits, finds the "fake" column robustly via clf.classes_, computes EER/bal-acc/F1/AUC.
  • main() — extracts train/test features for two feature sets (raw MFCC, and Transfer(GNB+NMF)) × 4 classifiers, prints a comparison table, reports the best-EER row, saves baseline_results.csv.

deepfake_dataset.py

manifest → log-mel spectrogram Dataset, plus the shared audio decoder that fixes the "silence→real" bug
In paper

Top-level constant: LABEL_TO_IDX = {"real":0, "fake":1} — the canonical label ordering used everywhere in Phase 1 and reused (imported) into Phase 2/3's darad_dataset.py.

  • load_audio(filepath) -> (Tensor[ch,samples], sr) — shared decoder. Tries soundfile.read first; on any exception falls back to librosa.load(..., mono=False) (ffmpeg-backed).
    Critical, non-obvious detail. libsndfile silently fails to decode a large fraction of ASVspoof2021 FLAC files ("flac decoder lost sync") even though they're valid. Without the fallback, roughly half of the real-class ASVspoof audio silently loaded as zeros, teaching the model a "silence → real" shortcut. This function is the fix, and it is reused by paper_baseline.py, darad_dataset.py, and (structurally, reimplemented rather than imported) every Phase‑3 decode() function.
  • class DeepfakeAudioDataset(Dataset) — __init__(csv_path, sample_rate=16000, duration_sec=4.0, n_mels=80, n_fft=400, hop_length=160, random_crop=True): computes target_len = sr*duration (64000 samples), builds reusable MelSpectrogram+AmplitudeToDB transforms. _load_and_fix_length: downmixes, resamples, zero-pads if short or random-/center-crops if long (random for train-time augmentation). __getitem__: wraps loading in try/except, substituting a zero waveform (with a printed warning) on failure rather than crashing the DataLoader worker; applies mel+dB transforms.
  • compute_class_weights(df) -> Tensor — inverse-frequency weights [w_real, w_fake], total/(2*count) per class, guarded against div-by-zero. Feeds train.py's CrossEntropyLoss(weight=...).
Paper traceREADME's "Note on data decoding" section narrates this fix explicitly.

model.py

AttentiveSpecCNN — the proposed detector, CNN + learnable temporal-attention pooling
In paper
  • class ConvBlock(nn.Module) — Conv2d(3×3, pad 1) → BatchNorm2d → ReLU, optional MaxPool2d.
  • class TemporalAttentionPool(nn.Module) — (B,C,T) → (context (B,C), attn (B,T)). A single Linear(channels,1) scores each time frame; softmax over time normalizes weights to sum to 1; context = batched-matmul weighted sum of per-frame channel vectors. This is the paper's stated novelty replacing the reference paper's static MFCC→GNB→NMF chain, and the returned attn doubles as the explainability signal visualized in explain.py.
  • class AttentiveSpecCNN(nn.Module) — input_norm (BatchNorm2d on raw dB values) → 4 ConvBlocks (1→16→32→64→128 channels, each halving freq & time) → mean-pool over frequency → TemporalAttentionPool(128) → head (Linear→ReLU→Dropout(0.3)→Linear(64,2)). forward(x, return_attn=False) stashes the conv feature map on self._last_fmap (kept for external use, though explain.py actually re-hooks it rather than reading this attribute). Output column order [real=0, fake=1] matches LABEL_TO_IDX.

__main__ block: shape smoke-test on a random (4,1,80,401) input.

Paper tracereport_tables.tex's tab:config describes this exact architecture (CNN + temporal attention pooling).

metrics.py

EER computation and the full evaluation report — the field-standard metric everything is judged on
In paper

Convention throughout: label 1=fake (positive class), scores = model's P(fake).

  • compute_eer(labels, scores) -> (eer, threshold) — computes roc_curve, fnr = 1-tpr, finds the index minimizing |fnr-fpr| via np.nanargmin (the EER operating point), returns the average of fpr and fnr at that index.
  • evaluation_report(labels, scores, threshold=0.5, verbose=True) -> dict — bundles accuracy, balanced accuracy, F1(fake), AUC, EER, and (if verbose) a full classification_report.
Paper traceNot named directly in the tex, but is the metric-computation backbone behind every EER number reported anywhere in either draft — explicitly called out in CLAUDE.md as "the field-standard number everything is judged on, not raw accuracy," which is itself the paper's core methodological critique of the reference paper's 84–93% accuracy-with-0-recall failure mode.

cross_dataset.py

leave-one-source-out generalization study — the AUC collapse that motivated the whole cross-corpus research direction
In paper

Constant: SOURCES = {"ASVspoof": "dataset_1_asvspoof2021_DF", "dataset_2": "dataset_2_seedtts_style", "MLAAD": "dataset_3_mlaad_v5"}.

  • build_fold(df, holdout, seed, out_dir, test_cap=4000) -> (train_csv, test_csv, train_bal, test_df) — training pool = all sources except the held-out one, balanced via build_balanced_subset.sample_fake (directly imported/reused, not reimplemented). augment.py

reference CPU/numpy RawBoost implementation (Tak et al., ICASSP 2022)
Indirect

Purpose. Perturbs convolutive coloration, impulsive device noise, and stationary colored noise so "clean vs. telephone/codec" stops being a shortcut proxy for real/fake.

  • _gen_notch_coeffs(nBands, minF, maxF, minBW, maxBW, minCoeff, maxCoeff, minG, maxG, fs) — builds an FIR filter as the product of nBands random bandstop notch filters via scipy.signal.firwin, applies a random gain normalized against the filter's peak response.
  • _filter_fir(x, b) — applies via lfilter with a specific right-pad-then-trim delay-compensation scheme — the exact scheme rawboost_gpu.py later has to reproduce algebraically for batched GPU convolution.
  • LnL_convolutive_noise(x, fs, N_f, nBands, ...) — linear + non-linear multi-band convolutive noise: for i in range(N_f), filters x**(i+1) and sums (algo=1).
  • ISD_additive_noise(x, P, g_sd) — impulsive signal-dependent additive noise on a random index subset (algo=2).
  • SSI_additive_noise(x, fs, SNRmin, SNRmax, ...) — stationary colored noise at a random target SNR (algo=3).
  • class RawBoost — _apply(x, algo) dispatches 1=LnL, 2=ISD, 3=SSI, 4=all three in series (default), 5=LnL+ISD, 0=random pick. __call__(wav) accepts torch or numpy, guarantees output length matches input.
Paper tracemain.tex l.1058–1062: "our batched-GPU RawBoost reimplementation… verified against the reference implementation to within 5×10⁻⁷ relative error" — augment.py is that reference implementation, described but not named.

losses.py

DA-RAD's domain-adversarial & Real-Anchored losses — all validated harmful
Indirect
PROJECT_LOG §4 verdict: every loss in this file was validated as harmful. GRL was "catastrophically unstable"; Real-Anchor "collapsed the model to chance" (50% EER).
  • _GradReverse(torch.autograd.Function) / grad_reverse(x, lambd=1.0) — standard DANN gradient-reversal: identity forward, negated+scaled gradient backward.
  • class DomainAdversarialLoss(nn.Module) — 2-layer MLP domain classifier behind grad_reverse; cross-entropy against domain labels, but the reversed gradient pushes the encoder toward domain-indistinguishable embeddings. lambd meant to ramp 0→1 (via trainer.py's grl_lambda).
  • class RealAnchoredContrastiveLoss(nn.Module) — the paper's stated (abandoned) novelty. L2-normalizes embeddings, splits real/fake by label. Real-real attraction: cosine-similarity pairs among real embeddings, cross-domain-only by default (deliberately excludes same-domain pairs — prevents a trivial "align only within one corpus" degenerate solution). Real-fake separation: hinge relu(margin - ||e_real - e_fake||) over all cross pairs via torch.cdist. Fakes are never pulled toward each other — deliberate asymmetry vs. ASDGLoss, justified as "fake artifacts are generator-specific; forcing them together is the wrong inductive bias."
  • class ASDGLoss(nn.Module) — prior-work-style baseline (Xie et al. IEEE TIFS 2024) built specifically as the "what if we also cluster fakes" ablation counterpart. Shares the real-real term byte-for-byte with the anchor loss; adds a fake-fake separation hinge on cosine similarity.

Self-test constructs a "clustered fakes" geometry where RealAnchoredContrastiveLoss stays near-zero (fake clustering invisible to it by design) while ASDGLoss is measurably higher — a hard assertion the two losses diverge as intended.

Paper traceNarrated qualitatively in main.tex's "What did not work" / PROJECT_LOG §4. Note: the paper's actual DANN baseline table (tab:dann) is a separate, later, to-convergence implementation in analysis_pipeline.py/asdg_pipeline.py — this file's GRL is the earlier, abandoned DA-RAD pilot only, not what backs tab:dann.

tta.py

the validated method as a standalone CLI + Tent baseline
In paper

Constants: DEV="cuda", CKPT="protocols/ft_xlsr.pt", TARGET="protocols/protoB_itw_test.csv".

  • build_source() — instantiates DARADModel(SSLFrontend(..., n_trainable_layers=4)), loads the fine-tuned checkpoint with strict=False (checkpoint only has the trainable subset).
  • select_tta_params(model) — freezes everything, then unfreezes only LayerNorm modules inside the top-4 transformer layers plus the full projection/classifier/pool heads. This is the "top-LayerNorm-only fine-tuning" detail — a deliberately tiny trainable set, cheap to adapt and less prone to catastrophic forgetting than full fine-tuning.
  • score_all(model, loader) — @torch.no_grad(), returns labels, P(fake), and L2-normalized embeddings.
  • _augment(wav) — the channel perturbation used for consistency: gain ∈ U(0.7,1.3) + 0.005·randn noise.
  • adapt(model, loader, mode, use_st, use_anchor, use_cons, epochs=4, lr=1e-4, q=0.3, margin=1.0) — the core TTA loop. Each epoch, re-scores the whole pool fresh (pseudo-labels compound on the model's own drifting confidence). For mode="realmanifold": computes symmetric quantile thresholds lo,hi = quantile(scores,q), quantile(scores,1-q) — this file's default is q=0.3 (bottom/top 30% each, 60% of the pool labeled), which is a wider net than the "~15%" figure PROJECT_LOG's narrative summary sometimes quotes elsewhere — the exact quantile is a tunable knob swept later in overnight_pipeline.py. rawboost_gpu.py

batched-GPU RawBoost, numerically verified against augment.py's reference
In paper

Why it exists. augment.py's CPU/numpy implementation is strictly per-clip and mis-flattens a batched tensor if handed one directly; the GPU-resident-cache pipelines (protocol_a.py) are deliberately DataLoader-free, leaving nowhere to hook a per-clip CPU augmenter without a slow Python loop or reintroducing worker processes (previously exhausted shared memory).

Design rationale (from docstring): profiling showed coefficient generation is cheap (~3ms/clip) but lfilter over 64k samples is ~90% of cost (~60–180ms/clip). Solution: keep random-parameter generation on CPU/numpy in the exact same draw order as the reference (so exact equivalence is testable), move the FIR filtering to batched grouped conv1d on GPU.

  • _fir_batch(x, kernels) — zero-pads ragged per-clip kernels to Kmax, flips them (conv1d cross-correlates, flipping restores true convolution matching lfilter), runs grouped conv1d (groups=B, one kernel per "channel"), applies the per-clip causal-delay left-shift via torch.gather.
  • _norm_wav_batch(x, always) — batched peak-normalize.
  • lnl_convolutive_batch, isd_additive_batch, ssi_additive_batch — batched versions of the three augment.py algorithms, each documented against the reference; ISD collapses to a single elementwise multiply once the ragged per-clip index draws are done on CPU.
  • rawboost_batch(x, sr, algo, bank, **overrides), build_coeff_bank(n, sr, biased, **overrides), class RawBoostGPU — public API. RawBoostGPU pre-generates a coefficient bank (default 4096) up front and samples from it instead of fresh-generating every call — docstring reports 312ms/batch fresh generation (159ms of it CPU coefficient gen) vs. near-zero with a bank, ~11 hours saved across a full 20-fold grid.

Self-test validates _fir_batch against augment._filter_fir (rel. error <1e-4), end-to-end B=1 equivalence against augment.RawBoost under matched seeds (rel. error <1e-3), and bank-mode statistical equivalence (0.5×–2× magnitude of fresh generation).

adaptive_tta.py

pure-numpy, CUDA-free schedules for q/λ/E — the module that let all three mechanisms be validated (2 killed, 1 shipped) without spending GPU time
Indirect

Purpose. Deliberately zero CUDA/torch/pipeline imports, no module-level state — every function takes plain numpy arrays and returns plain numbers, so the whole adaptive signal is unit-testable on synthetic score arrays on a CPU (test_adaptive_tta.py). That is what let three proposed mechanisms be tested and two of them killed before any GPU time was spent.

Constants: LAMBDA_MAX=0.3, Q_CAP=0.3, Q_START=0.1, Q_GRID=(0.05,...,0.45), CHURN_TAU=0.5, E_MIN=2, E_MAX=8, STOP_TOL=0.002, DIVERGE_RATIO=1.5. LAMBDA_MAX/Q_CAP are kept as schedule ceilings specifically so the low-churn regime reproduces the published fixed config exactly rather than drifting from it.

  • pseudo_labels(s, lo_frac, hi_frac) — confident-tail labelling (-1/0/1). Deliberately byte-for-byte the same rule as extended_pipeline.py's tail cut, including assignment order (real first, fake second, so an overlap resolves to fake) — required for the adaptive path to be checkably reducible to the published one.
  • tail_cuts(s, lo_frac, hi_frac) — the absolute score thresholds the fractions imply.
  • view_churn(s, s_aug, lo_frac, hi_frac) -> (c_view, c_null) — fraction of confident clips whose tail assignment flips under augmentation, thresholded at the clean view's cuts (re-quantiling the augmented view would renormalize away the exact drift being measured). c_null is the closed-form churn an independent/uninformative ranking would produce, so normalizing by it makes "flips half as often as chance" scale-free rather than a new hand-picked constant.
  • epoch_churn(pl_prev, pl_now) — flip rate between two epochs' labels, restricted to clips confident in both epochs (so the q-ramp widening the confident set isn't miscounted as instability). Kept for the trace only — not a stopping signal (see next).
  • score_shift(s_prev, s_now) — mean per-clip |Δscore| between epochs. Replaces label churn as the stopping signal after label churn measured exactly 0.0000 on a real run (quantile-cut labels don't move unless the ranking reorders; self-training sharpens the boundary without reordering) and stopping on it fired at E_MIN every time, costing EER (10.16 vs. 9.38 fixed).
  • lambda_from_churn(c_view, c_null, lam_max) — λ = lam_max · clip(1 - c_view/c_null, 0, 1). Defined but not used by the shipped method — this is the mechanism test_adaptive_tta.py check [2] proves is confounded by augmentation magnitude, kept in the module as a documented negative result rather than deleted, so it isn't rediscovered and re-tried later.
  • estimate_prevalence_guarded(scores, min_prior=0.02, max_prior=0.98, bic_margin=0.0) -> (pi_real, bic_delta, shrunk) — reimplements protocol_a.py's validated 2-component-GMM prevalence estimator (same params, so the un-shrunk path returns the identical number), reimplemented here rather than imported because protocol_a.py runs torch/CUDA setup at module scope and this module must stay CPU-only. The guard is new: fits both a 1- and 2-component GMM, and if the 2-component fit doesn't beat the 1-component fit on BIC, falls back to π=0.5 (the symmetric budget the published method already uses) rather than trust a possibly-wrong split. Motivated by a real failure: on the RawBoost-retrained model the un-guarded estimator returned 0.458 against a true 0.025 — an 18× error that had silently driven a whole protocol run into the ground.
  • tail_budget(q, pi_real) -> (lo_frac, hi_frac) — splits the total confident-label budget 2q by prevalence; at pi_real=0.5 reduces identically to the symmetric (q,q) split, so on the balanced leave-one-corpus-out grid this machinery is a no-op and only the q-ramp changes anything. Bites specifically on skewed pools like Protocol A's 97.5%-spoof DF-eval.
  • select_q_max(s, s_aug, pi_real, grid, cap, tau) — NOT used by the method (docstring says so explicitly), retained for the analysis table only. Inherits the same augmentation-magnitude confound as lambda_from_churn: on real target audio it returns the grid minimum (0.05) regardless of corpus. The method instead uses a hard q_max=Q_CAP and lets the curriculum ramp + prevalence split do the adapting.
  • q_schedule(epoch, n_epochs, q_max, q_start=Q_START) — linear curriculum ramp from a strict high-purity tail (Q_START=0.1) up to q_max (the published Q_CAP=0.3 ceiling) — early epochs buy fewer, more-trustworthy pseudo-labels since the model is still miscalibrated on the target and a wide tail early would let confirmation bias compound. n_epochs is always E_MAX so the ramp's shape doesn't depend on when adaptive stopping happens to cut the run short.
  • should_stop(shift_history, epoch, min_epochs=E_MIN, max_epochs=E_MAX, tol=STOP_TOL, diverge_ratio=DIVERGE_RATIO) -> (stop, reason) — stops on "converged" (shift below tolerance), "diverging" (two consecutive rises above 1.5× the running minimum — deliberately requires sustained divergence after a single-epoch blip cut a healthy smoke run short at epoch 6), or "max_epochs". Deliberately biased toward running the full 8-epoch budget: every swept point in the existing hyperparameter sweep says more epochs help, so this is framed as a safety valve against a run that has stalled or diverged, not an efficiency optimization trying to shave epochs off a healthy run.
  • collapsed(s, min_std=1e-3, min_tail_gap=1e-3, q=0.1) -> (collapsed, reason) — flags non_finite_scores, score_std_collapse, or tails_merged. Insurance against the Tent-style failure mode main.tex describes as undetectable in advance (a run looking healthy right up until its score distribution collapses to ~49.5% EER) — can't predict it, but can notice it happening and hand back the pre-adaptation model instead of a catastrophic one.

tuesday_runner.py

unattended, resumable job-queue supervisor for the P1 compute package
Support

Purpose. Meant to be started with nohup ... & and left alone. Works a fixed, priority-ordered JOBS list (ext seed 4 → ext seed 5 → asdg 3,4 → dann 3,4 → ext 6–9) against a 23h deadline (TUESDAY_BUDGET_H), skipping any job whose estimate no longer fits the remaining time rather than blocking on it. Ordering is by marginal statistical value per GPU-hour, not by ICASSP_PLAN.md's own numbering — ext seed 5 is prioritized above everything else in the queue because it's the seed that first makes a per-target significance claim possible at all (see above).

  • row_count(path) -> int — counts data rows (minus header) in a results CSV; 0 if the file doesn't exist yet.
  • mlaad_meta_count() / have_mlaad() — a complete MLAAD v5 has 154 meta.csv files across 38 languages; have_mlaad checks against a deliberately lower threshold (MLAAD_MIN_META=100) so slightly different Kaggle packagings still pass, while still rejecting a handful of files left by a partial download. Docstring records the earlier bug this replaced: a version that returned True on the first meta.csv found would have accepted a 31GB half-download from two concurrent downloaders and silently trained seeds 5–9 on a different source composition than seeds 0–4.
  • run_mlaad() -> bool — downloads MLAAD (~57GB) via the kaggle Python API (not the CLI — pip --user puts the CLI binary in ~/.local/bin, off PATH on a stock JupyterLab image, which cost a silent hours-long failure the session before this one). If a partial copy is detected it's deleted and re-fetched from scratch rather than resumed onto, since the kaggle client won't repair what it thinks it already has.
  • acquire_lock() / release — PID-file lock (tuesday_runner.lock) refusing to start a second instance. Docstring: two live supervisors were observed running concurrently (33 and 25 minutes in) before this existed, both about to drive independent 57GB MLAAD downloads into the same directory.
  • publish_dann() — merges analysis_res/results_dann.csv (where analysis_pipeline.py's record() actually writes) into the root-level results_dann.csv that stats_tests.py reads, keyed on (seed, target, method) with new rows winning ties. See the callout below — this replaced a plain shutil.copy that would have deleted seeds 0–2.
  • main() — acquires the lock, loads tuesday_state.json (a completed-job list, so a re-run after any interruption repeats nothing), then for each job: hard-gates on have_mlaad() (every remaining job trains source models, and running without MLAAD wouldn't error — it would silently train on a different, non-comparable source composition), skips if the estimate doesn't fit the remaining budget, runs the job as a subprocess under a hard timeout, and — the key check — treats a clean exit as a failure if the job's declared output CSV gained no rows. Calls publish_dann() and re-runs stats_tests.py unconditionally at the end, even if every job was skipped, since it's seconds of CPU and makes whatever landed immediately usable.
Three bugs this session found in itself, fixed in three follow-up commits (88e0ef2, 2b6e675, 1e5e90e):
  1. EXT_SEEDS lived inside extended_pipeline.py's else: branch, but PILOT defaults to True, so that branch never ran. Every "ext seed N" job silently ran the pilot config instead (seed 0, one target), found the fold already recorded, and exited 0 in ~72s. A 4.5h session produced nothing except the ASDG seeds.
  2. The supervisor treated exit code 0 as success, so those six no-op jobs were logged "ok" into tuesday_state.json — which would have made them skip again on every future run too. Fixed by the row-count check in main() above: a clean exit that adds no rows is now FAILED, not done.
  3. The DANN job's output was checked against results_dann.csv in the repo root, but analysis_pipeline.py's record() writes under analysis_res/ — so a DANN run that may well have succeeded looked like a failure. Worse, a naive publish step (plain shutil.copy) would have overwritten 12 rows (seeds 0–2) with 8 (seeds 3–4) the moment the row-count check above was fixed and let the DANN job report success; it "survived" only because the old copy's own guard (row_count(src) > row_count(dst), 8 > 12) happened to be false — luck, not a safeguard. publish_dann() now merges by key instead of copying.

Likely trace

The original "cloud sweep" shared one continuous RNG stream across all configurations — adjacent sweep points differed partly by batch-order/augmentation noise rather than purely by the hyperparameter under test. This script re-seeds torch.manual_seed(RUN_SEED) before each configuration to remove that confound. Explicitly caveats: still one seed per point, not a full seed-repeated CI.
