0 — Environment setup

A venv lives in env/; pinned versions matter (numpy/pandas ABI compatibility, librosa/numba deliberately removed to avoid a conflict) — don't casually bump requirements.txt.

source env/bin/activate
pip install -r requirements.txt   # only if env/ needs rebuilding

Everything below assumes this venv is active and the working directory is the repo root.

1 — Phase 1: baseline + AttentiveSpecCNN

Runs locally (CPU is workable; a small GPU speeds up train.py). This is the fully reproducible half of the project — every step below is deterministic given the fixed --seed defaults and produces the exact tables cited in report_tables.tex.

1Build the manifest

python build_manifest.py --root data --out manifest.csv

Walks the 6 raw corpora under data/ (ASVspoof2021 DF, the LibriSpeech-real/TTS-fake set, MLAAD v5, ASVspoof2019 LA, In-the-Wild, Arabic ArAD) and merges them into one labeled, speaker-tagged CSV. Expect real/fake totals printed at the end — sanity-check against Table I in the paper (19,251 real / 595,513 fake before balancing) before moving on; a wildly different count usually means a corpus directory is missing or partially downloaded.

2Build the balanced subset

python build_balanced_subset.py --manifest manifest.csv --out manifest_balanced.csv

Water-fills the ~97%-fake manifest down to a class-balanced, generator-diverse subset (default --ratio 1.0, i.e. fake count ≈ real count). Deterministic given --seed (default 42).

3Speaker-disjoint split

python split_manifest.py --manifest manifest_balanced.csv --out_dir splits

Produces splits/train.csv, val.csv, test.csv via StratifiedGroupKFold grouped on the speaker column, so no speaker's utterances cross a split boundary. The script asserts empty pairwise speaker-set intersections and will raise if that assertion fails — treat that as a hard stop, not something to catch and ignore, since it's the leakage fix over the original paper's methodology.

4Classical baseline (Table II, GNB/NMF rows)

python paper_baseline.py

MFCC→GNB→NMF→{GNB,LR,RF,KNN} reproduction of the original paper. First run extracts and caches MFCC features under features_cache/ (MD5-keyed on the file list, so re-runs on the same split are fast); writes baseline_results.csv. Expect ~13% EER / ~85% bal-acc for the best classical row — that's the number the DL model has to beat.

5Train AttentiveSpecCNN

python train.py --epochs 15

Key flags: --batch_size (64), --lr (1e-3), --workers (8), --seed (42), --out (checkpoint path, default attentive_spec_cnn.pt). Trains with class-weighted CrossEntropyLoss, checkpoints on val EER improving (not val loss), reloads the best checkpoint at the end, evaluates on the held-out test split, and merges the result row into baseline_results.csv (replacing any prior AttentiveSpecCNN row, so reruns don't duplicate) plus writes results.csv. Expect ~4.81% EER / ~93.84% bal-acc in-domain.

If real-class metrics look suspiciously bad (e.g. near-0 real recall on ASVspoof-heavy splits), check that deepfake_dataset.load_audio's librosa fallback is actually firing — libsndfile silently fails to decode a large fraction of ASVspoof2021 FLACs, and without the fallback roughly half the real-class audio loads as zeros, teaching a "silence→real" shortcut. This should not reproduce on a clean checkout (the fallback is unconditional), but it's the single most likely cause if numbers regress after touching deepfake_dataset.py.

6Explainability figures

python explain.py --n 6

Grad-CAM + attention-curve figures for a balanced sample of test clips (or one file via --file). Needs the checkpoint from step 5. Produces the PNGs referenced by fig:explain in report_tables.tex.

7Leave-one-source-out generalization study

python cross_dataset.py --epochs 10

Trains 3 from-scratch folds (hold out ASVspoof / dataset_2 / MLAAD in turn, train on the rest), reports EER/bal-acc/AUC where the held-out fold has both classes, and fake_recall for MLAAD (fake-only, no EER possible). Writes cross_dataset_results.csv. Expect AUC to collapse toward 0.42–0.56 out-of-source — this is the result (Table III / fig:cross) that motivated the entire Phase 2/3 cross-corpus research line, so a collapse here is correct, not a bug to chase.

2 — Phase 2/3 core: DA-RAD (failed) & TTA (working)

These are driven by shell wrappers rather than a single script, and need a GPU (fine-tuned XLS-R encoder). All four hardcode a specific cloud-machine path (cd /home/general/Desktop/deepfake_project) inside the .sh files — edit that line, or just run the underlying trainer.py/tta.py invocations directly, if reproducing somewhere else.

1DA-RAD ablation (negative result, kept for the paper's ablation table)

bash run_ablation.sh    # frozen encoder: xlsr / +rawboost / +grl / +darad
bash run_gonogo.sh      # unfrozen top-4 XLS-R layers: xlsr / +anchor / +darad

Writes ablation_results.txt / gonogo_results.txt. Expected outcome: every DA-RAD component (gradient-reversal, Real-Anchored contrastive) makes EER worse — GRL is described in PROJECT_LOG.md §4 as "catastrophically unstable," Real-Anchor as collapsing the model to ~50% EER (chance). Do not treat a bad result here as something to debug; it's the recorded negative finding.

2Test-time adaptation (the method that works)

bash run_tta_confirm.sh      # 3 seeds x 2 OOD targets, appends to tta_results.txt
bash run_tta_validation.sh   # multi-seed + component ablation (st_only/st_anchor/st_cons) + inductive check

run_tta_validation.sh truncates/rewrites tta_results.txt at the start — run this one before run_tta_confirm.sh if you want both sets of numbers in the same file, since the confirm script only appends. Both drive tta.py directly (--mode realmanifold --no-anchor and friends); see tta.py's own docstring for the full flag list (defaults: q=0.3, λ=0.3, E=4).

3 — Phase 3 extended: the main cross-corpus grid

This is the heavy, incremental, GPU-hours-scale run — the primary source of tab:main, the backbone table, and the DANN/divergence/per-language tables. Per RUN_GUIDE.md, this normally runs from overnight_pipeline.ipynb (decodes all audio once into a single fp16 GPU tensor, no DataLoader workers — shared-memory workers previously crashed), but the individual pipeline scripts below can also be invoked standalone, which is what the Tuesday supervisor (§5) actually does.

1Main grid (4 targets × seeds)

# full run, all default seeds:
python extended_pipeline.py
# a single additional seed (what the Tuesday supervisor uses to extend coverage):
EXT_SEEDS=5 python extended_pipeline.py

Appends to results_ext.csv, one row per (target, seed, method) fold, with its own resume guard — a fold already present is skipped, so re-running after an interruption costs no repeated GPU time. Reuses the 12 ckpt_ext/ source checkpoints once they exist rather than retraining. First run on a machine without data/mlaad triggers a 45GB MLAAD auto-download — see §7 before starting this unattended.

2Post-hoc analysis (divergence, DANN, per-language, t-SNE)

python analysis_pipeline.py               # all 4 parts
ANALYSIS_PARTS=dann DANN_SEEDS=3,4 python analysis_pipeline.py   # DANN only, specific seeds

Run after extended_pipeline.py — it explicitly says so in its own docstring, since it reuses those checkpoints. ANALYSIS_PARTS lets you re-run just one of the 4 parts (divergence / DANN / per-language / t-SNE) without recomputing the others.

DANN output path. record() writes DANN results under analysis_res/results_dann.csv, not the repo-root results_dann.csv that stats_tests.py reads. If running this manually (not via tuesday_runner.py, which does this for you via publish_dann()), merge the two by (seed, target, method) — do not cp/shutil.copy one over the other, since analysis_pipeline.py only writes the seeds it was asked for and a plain copy will delete whichever seeds aren't in the smaller file.

3ASDG baseline

python asdg_pipeline.py
ASDG_SEEDS=3,4 python asdg_pipeline.py   # extend seed coverage the same way as EXT_SEEDS

Writes/extends results_asdg.csv. Same resume-by-fold guarantee as extended_pipeline.py.

4 — Statistical significance

python stats_tests.py

Pure CPU, seconds, no GPU — reads results_ext.csv / results_dann.csv / results_asdg.csv, pairs runs by (target, seed), and reports pooled Wilcoxon signed-rank (ours vs. source/tent/st_only/dann/asdg) plus 10k-resample bootstrap 95% CIs per target. Writes stats_results.csv.

n matters here more than anywhere else in the repo. Wilcoxon at n=5 pairs cannot reach p<0.05 at all — the floor is the combinatorial 2/2⁵=0.0625, not a power/effect-size problem. n=6 gives 2/2⁶=0.031. If a per-target p-value looks stuck above 0.05, check len(keys) (printed as n= in the output) before concluding the effect isn't significant — it may just mean that target hasn't accumulated a 6th seed yet.

Safe (and cheap) to re-run after every partial GPU session — this is exactly what tuesday_runner.py does unconditionally at the end of its run, even if every job in its queue was skipped.

5 — Unattended cloud session (Tuesday P1 supervisor)

The recommended way to extend the seed grid on a fresh cloud GPU box without babysitting it. This is what steps 3–4 above look like when automated end-to-end with resumability and a wall-clock budget.

TUESDAY_BUDGET_H=23 nohup python tuesday_runner.py > logs/tuesday.out 2>&1 &

Works a fixed priority queue (ext seed 4 → ext seed 5 → asdg 3,4 → dann 3,4 → ext 6–9) against the budget, skipping any job that no longer fits the remaining time. Hard-gates every job on a complete MLAAD download (154+ meta.csv files) before running anything, since every remaining job trains source models and a partial/missing MLAAD would silently train on a non-comparable source composition rather than error. Refuses to start a second instance (PID-file lock at tuesday_runner.lock) — if you need to take over from a dead process: pkill -f tuesday_runner && rm tuesday_runner.lock.

tail -f run_log_tuesday.txt          # live progress
cat tuesday_state.json               # which jobs have completed
Fully resumable by design. Every underlying pipeline (extended_pipeline.py, asdg_pipeline.py, analysis_pipeline.py) appends to its CSV per fold with its own (seed, target) resume guard, and the supervisor keeps tuesday_state.json on top of that. Killing and re-launching tuesday_runner.py at any point repeats no completed GPU work. The one exception is DANN, which has no resume guard of its own — the supervisor passes it explicit DANN_SEEDS=3,4 so it can't duplicate seeds 0–2, and merges (not copies) its output back to the root results_dann.csv.

A job is only marked done if its declared output CSV actually gained rows on a clean exit — a script that exits 0 without adding data is logged and treated as FAILED, not silently accepted, after an earlier session lost 4.5h of budget to exactly that failure mode (see tuesday_runner.py's entry in CODE_WALKTHROUGH.html §Phase 5 for the full story).

6 — Phase 4: adaptive q/E (validated mechanism, excluded from this paper)

Scope note. ICASSP_PLAN.md §P3 lists adaptive q/E and Protocol A as deliberately excluded from this paper's submission. Reproduce this only if you're specifically investigating the adaptive-schedule side project, not as part of getting the paper's headline numbers.

1CPU-only validation (no GPU needed)

python test_adaptive_tta.py      # 36 checks, includes 3 confounded mechanisms as recorded negative results
python verify_reduction.py       # MUST pass before trusting any adaptive-vs-fixed comparison

verify_reduction.py asserts that the adaptive loop with both switches off is bitwise identical to the published, non-adaptive adapt(). If it fails, every subsequent adaptive-vs-fixed result is confounded by the refactor itself, not by the schedules being tested — do not proceed past a failure here.

2Smoke run (small subsets, sanity-check only)

python adaptive_pipeline.py

Writes *_smoke.csv outputs on ~128 clips (~0.8% per-clip resolution). This validates that the mechanism runs end-to-end, not any actual result — don't quote these numbers.

3Real run (needs a GPU box with no local data — see MONDAY_HANDOFF.md)

ADAPTIVE_SMOKE=0 python adaptive_pipeline.py    # 4 targets x seeds 0-2

MONDAY_HANDOFF.md is the full runbook for a fresh cloud session: required uploads (ckpt_ext/ source checkpoints, kaggle.json, the Protocol A RawBoost checkpoint, and its results CSV) to avoid a ~3h retrain and a 57GB MLAAD download that this path never actually needs. Time budget: ~40min setup, ~5min verify_reduction.py gate, ~6h for the grid, ~1h for Protocol A's adaptive arm.

8 — Rebuilding the paper PDF

main.tex (the general IEEE draft) and main_icassp.tex (the ICASSP-scoped draft) both live at the repo root alongside compiled main.pdf / main_icassp.pdf. Rebuild with a standard LaTeX toolchain, e.g.:

latexmk -pdf main.tex
latexmk -pdf main_icassp.tex

Figures referenced from the tex sources (fig_*.png) are produced by explain.py, cross_dataset.py, make_figure.py, make_perlang_figure.py, and make_auc_gain_scatter.py — generate results first (§1–§4 above), then figures, then compile.
